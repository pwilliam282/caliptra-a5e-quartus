# Nios V/m host + Caliptra 1.x on Agilex 5 E (A5EC065BB32AE6S)

Compile study: an Intel **Nios V/m** CPU acts as the SoC "mailbox host" for **Caliptra 1.x**
(chipsalliance/caliptra-rtl v1.1 @ 5f85fb4, passive mode) over Caliptra's **APB** subordinate.
Quartus Prime Pro 25.3 (Docker `alterafpga/quartuspro-v25.3:agilex5`). **Pinout TBD** – all I/O
except `clk`/`reset_n` are virtual pins; nothing here is board-proven yet.

## Architecture
```
 clk ─┬─────────────────────────────────────────────────────────────┐
      │  nios_caliptra_sys (Platform Designer)                      │
      │  Nios V/m ─AXI4-lite─► interconnect ─┬─ ram (64 KiB OCM, reset vector 0x0)
      │                                      ├─ jtag_uart (stdout)
      │                                      ├─ ctrl_pio  (out) ──► cptra_pwrgood / cptra_rst_b / BootFSM_BrkPoint
      │                                      ├─ status_pio(in)  ◄── ready_for_* / mailbox_* / errors / etrng_req / gen_out[23:0]
      │                                      ├─ magic_pio (out) ──► led[7:0] + Caliptra generic_input_wires[31:0]
      │                                      └─ caliptra_win (mm_bridge, 256 KiB) ─► exported Avalon master
      │                                                              │
      │   window decode in rtl/nios_caliptra_top.sv ◄────────────────┘
      │     ├─ 0x0_0000 rtl/soc_fw_store.sv   FW bundle ROM (M20K, ../fw/caliptra-fw-bundle.hex)  = "SoC boot flash"
      │     ├─ 0x1_F000 rtl/soc_fuse_ctrl.sv  fuse controller IP (../fw/fuse_image.hex)           = "SoC OTP + fuse sequencer"
      │     │             └─ APB requester (owns APB while pushing fuses) ─┐
      │     └─ 0x2_0000+ rtl/avmm_to_apb.sv (PAUSER = 1) ──── APB mux ◄─────┘
      │                                                      │ APB3 (PADDR[17:0])
      └──► caliptra_passive_top (../rtl) ─ Caliptra 1.x + M20K mailbox / ROM (../fw/caliptra-rom.hex) / ICCM / DCCM
```
Straps (`rtl/nios_caliptra_top.sv`): arbitrary **TEST** `cptra_obf_key`, lifecycle = UNPROVISIONED,
debug unlocked, JTAG/scan/itrng tied off (itrng_valid=0 → ETRNG mode).

## Address map (Nios data master; from generated `sw/bsp/system.h`)
| Base | Span | Block |
|---|---|---|
| 0x0000_0000 | 64 KiB | `ram` on-chip memory (code+data, init from `onchip_mem.hex`) |
| 0x0004_0000 | 112 KiB | `soc_fw_store` (inside `caliptra_win`): Caliptra 1.x FMC+RT bundle, read-only, word i at +4*i |
| 0x0005_F000 | 4 KiB | `soc_fuse_ctrl` (inside `caliptra_win`): ID 0x00, CTRL 0x04 (bit0 START, bit1 CLEAR), STATUS 0x08 (bit0 BUSY, 1 DONE, 2 ERR, 3 ready_for_fuses), COUNT 0x0C, FW_BYTES 0x10, NUM_FUSES 0x14 |
| 0x0006_0000 | 128 KiB | `caliptra_win` → Caliptra APB (window offset = APB address: mbox 0x2_0000, soc_ifc 0x3_0000) |
| 0x0008_0000 | 8 | `jtag_uart` |
| 0x0008_0010 | 16 | `ctrl_pio` bit0 pwrgood, bit1 cptra_rst_b, bit2 BootFSM_BrkPoint (reset 0 = held in reset) |
| 0x0008_0020 | 16 | `status_pio` bit0 ready_for_fuses, 1 ready_for_fw_push, 2 ready_for_runtime, 3 mailbox_data_avail, 4 mailbox_flow_done, 5 error_fatal, 6 error_non_fatal, 7 etrng_req, 31:8 generic_output_wires[23:0] |
| 0x0008_0030 | 16 | `magic_pio` → led[7:0] |
| 0x0008_0040 | 64 | Nios V timer_sw_agent (mtime) |
| 0x0009_0000 | 64 KiB | Nios V debug module |

Caliptra registers through the window (base 0x0004_0000 + offset):
`MBOX_CSR` 0x2_0000 (MBOX_LOCK 0x2_0000), `CPTRA_FLOW_STATUS` 0x3_003C (bit30 ready_for_fuses),
`CPTRA_HW_REV_ID` 0x3_00D4 (**expect 0x0000_0011** = CPTRA_GENERATION 1.1), fuses 0x3_0200…

## Boot flow (mimics a real Caliptra 1.x passive SoC)
| Real SoC block | FPGA stand-in here |
|---|---|
| Power/reset sequencer | `ctrl_pio` driven by Nios |
| OEM OTP fuses + fuse controller | `rtl/soc_fuse_ctrl.sv` + `../fw/fuse_image.hex` (generated by `../scripts/gen_fuse_image.py`) |
| SoC boot flash holding Caliptra FW | `rtl/soc_fw_store.sv` + `../fw/caliptra-fw-bundle.hex` (on-chip M20K, no external flash) |
| SoC TRNG (1.x ext. TRNG mode) | Nios `trng_service()` (xorshift — **TEST entropy only**) |
| SoC host CPU / mailbox driver | Nios V `sw/app/main.c` |

**Fuses.** In Caliptra 1.x fuses are not a Caliptra sub-block: the SoC must write all `FUSE_*` registers of
`soc_ifc` (APB 0x3_0200–0x3_0348, 83 words) after `ready_for_fuses`, then set `CPTRA_FUSE_WR_DONE`. `soc_fuse_ctrl`
does exactly that in hardware from its OTP image when Nios writes CTRL.START (it takes the APB for ~84 transfers,
then hands it back). UDS / field entropy are **not** readable by Nios (like real OTP; Caliptra FUSE regs are also
write-only from SoC). Fuse image (TEST): UDS = DEADBEEF,55AA0001..B; field entropy FE000000..7; vendor/owner PK hashes = 0
(1.x ROM skips the vendor key-hash check when unprovisioned & hash fuse = 0); SVNs/anti-rollback/LMS/lifecycle = 0;
SOC_STEPPING_ID = 1. Edit `scripts/gen_fuse_image.py` and re-run it to change (e.g. put your vendor PK hash when you sign your own FW).
This replaces OEM fuse OTP for FPGA bring-up only.

**Firmware download.** After `ready_for_fw_push` Nios acquires `MBOX_LOCK`, checks `MBOX_USER`=1, writes
`MBOX_CMD`=0x4657_4C44 (FIRMWARE_LOAD), `MBOX_DLEN`=109000, streams 27 250 words from `soc_fw_store` into `MBOX_DATAIN`,
sets `MBOX_EXECUTE`, polls `MBOX_STATUS` (2 = CMD_COMPLETE), clears EXECUTE, then waits `ready_for_runtime`.
`etrng_req` (status_pio bit7) is serviced in every wait loop: 12 words → `CPTRA_TRNG_DATA[0..11]` (0x3_0078..), `CPTRA_TRNG_STATUS`=2.

### MAGIC milestones (`magic_pio`, led = MAGIC[7:0])
| MAGIC | Meaning |
|---|---|
| 0x0000_0001 | Nios alive, releasing pwrgood / cptra_rst_b |
| 0x0000_0002 | `ready_for_fuses` seen, HW_REV_ID ok |
| 0x0000_0003 | mailbox VALID_PAUSER[0]=1 programmed + locked |
| 0x0000_0004 | `soc_fuse_ctrl` pushed 83 fuses + FUSE_WR_DONE (COUNT=84) |
| 0x0000_0005 | ROM booted to `ready_for_fw_push` |
| 0x0000_0006 | FIRMWARE_LOAD streamed + EXECUTE set |
| 0x0000_0007 | mailbox CMD_COMPLETE (FW accepted) |
| **0xCA11_F00D** | `ready_for_runtime` — Caliptra FMC+RT running (led = 0x0D) |
| 0xDEAD_0001 / 02 | timeout ready_for_fuses / bad HW_REV_ID |
| 0xDEAD_0003 / 04 / 05 / 06 | fuse ctrl ID wrong / fuse push timeout / fuse push error (PSLVERR or not ready) / FUSE_WR_DONE not set |
| 0xDEAD_0007 | timeout ready_for_fw_push |
| 0xDEAD_0008 / 09 | MBOX_LOCK timeout / MBOX_USER ≠ 1 |
| 0xDEAD_000A / 0B | mailbox status timeout / CMD_FAILURE (FW rejected) |
| 0xDEAD_000C / 0D | timeout ready_for_runtime / error flag at runtime |
| 0xDEAD_00FF | `cptra_error_fatal` during boot |

At 50 MHz the whole boot is ~24 M Caliptra cycles (~0.5 s) plus APB streaming time.
Simulation of the **real** top-level glue (window decode, fw store, fuse ctrl, APB mux, Caliptra + ROM) with a
behavioral Nios: `../sim/run_nios_top_fw.sh` (`../sim/tb_nios_top_fw.sv`, ~1 h in Verilator).
Note: after editing main.c, rerun `sw/build_app.sh` (with elf2hex) so `onchip_mem.hex` matches before synthesis.

## Rebuild
All Quartus/PD commands run inside Docker via `./dock.sh '<cmd>'` (needs `--net=host` + license
`LIC_HOST=/path/SW-AGILEX-5E.dat`; the fixed license is tied to the build host's NIC MAC).
```bash
# 1. Platform Designer system (regeneratable source = qsys/nios_caliptra_sys.tcl)
./dock.sh 'cd qsys && rm -rf ip nios_caliptra_sys.qsys && qsys-script --script=nios_caliptra_sys.tcl --quartus-project=none'
# 2. BSP + app CMake (already checked in under sw/bsp, sw/app)
./dock.sh 'niosv-bsp -c -s=qsys/nios_caliptra_sys.qsys -t=hal --cmd="set_setting hal.stdout jtag_uart; set_setting hal.stdin jtag_uart; set_setting hal.stderr jtag_uart" sw/bsp/settings.bsp'
./dock.sh 'niosv-app --bsp-dir=sw/bsp --app-dir=sw/app --srcs=sw/app/main.c --elf-name=caliptra_host.elf'
# 3. Compile app (any rv32 GCC; tested xPack riscv-none-elf-gcc 14.2 + cmake + ninja), makes onchip_mem.hex
RISCV_BIN=/path/to/xpack-riscv-none-elf-gcc/bin sw/build_app.sh
# 4. Synthesis (IP generate + quartus_syn).  'fit' also routes – needs >=32 GB RAM.
./run_nios_a5e_docker.sh syn
```
Quartus files: `nios_caliptra_a5e.qpf/.qsf` (paths relative: `../caliptra-rtl`, `../rtl`, `../quartus/syn_src`),
`nios_caliptra.sdc` (50 MHz clk). Order: build the app first so `onchip_mem.hex` exists before synthesis.
